AI Job Search Engine

A semantic job discovery engine built for a founding engineer take-home challenge. Uses multi-vector FAISS search, GPT-powered cross-title matching, geo-distance filtering, and conversational refinement to help users find relevant jobs from 100K US postings using natural language.

Overview

Modern job search is broken — job descriptions are messy, requirements are implied rather than labeled, and users think in intent ("something senior but not management", "remote-friendly startups") rather than keyword filters. This engine was built to solve that.

Given a dataset of 100,000 US job postings scraped from company career pages — each with raw text, GPT-extracted structured fields, and three pre-computed 1536-dimensional embeddings — the system delivers intelligent, natural-language job discovery with conversational refinement across multiple turns.

Built in ~16 hours across 4 days as a take-home engineering challenge for a startup's founding engineer role. Total API cost during development: ~$0.005.

Key Innovations

Multi-Query Cross-Title Matching

Traditional semantic search embeds the user's query as one vector — if the user says "data engineer", it only matches that exact phrasing. This system:

  1. GPT extracts related job titles that need similar skills but use different words
  2. Batch-embeds all variants in a single API call (negligible extra cost)
  3. Searches FAISS with each variant, keeping the MAX score per candidate

Example: "someone who manages projects" → primary: "project manager" + related: ["program manager", "scrum master", "delivery manager", "TPM"] → returns Scrum Masters, Project Managers, and Program Managers in one result set.

Geo-Distance Filtering

Instead of string-matching city names (which fails: "San Diego" ≠ "San Francisco" even though both contain "San"), the system uses haversine distance with a 50-mile radius:

  • Pre-computed coordinates for 1,000 US cities via Photon geocoder
  • Jobs within 50 miles of the requested city pass the filter
  • "San Diego" matches Chula Vista (7mi) and Carlsbad (32mi), but not LA (111mi) or SF (458mi)

Conversational Refinement

Multi-turn queries accumulate history and re-synthesize the full search intent each turn — not just additive filters:

  1. Turn 1: "data science jobs" → searches broadly
  2. Turn 2: "at social good non-profits" → GPT sees Turn 1 context, synthesizes "data science at mission-driven orgs"
  3. Turn 3: "make it remote" → GPT sees Turn 1+2, synthesizes "remote data science at social good orgs"

How Search Works

  1. Query Parsing: GPT-4o-mini analyzes the natural language query and extracts: focused search text, 3–5 related alternative job titles, structured filters (remote, location, salary, seniority, industry), and per-query weight tuning for the three embedding channels.
  2. Batch Embedding: The primary search text + all related titles are embedded in a single API call via text-embedding-3-small (1536 dimensions).
  3. Multi-Vector Search: Each embedding vector is searched against 3 FAISS indices:
    • Explicit (0.45 weight): Matches job title, listed skills, certifications
    • Inferred (0.30 weight): Matches implied qualifications, related roles
    • Company (0.25 weight): Matches company characteristics, industry, mission
  4. Score Aggregation: For each candidate job, we keep the MAX score across all query variants per index, then compute the weighted sum.
  5. Post-Filtering: Hard filters applied after scoring — geo-distance (50mi radius via haversine), remote flag, salary ranges, seniority with alias expansion.
  6. Ranking: Final results sorted by combined score, top-K returned with job cards showing title, company, location, salary, skills, and description snippet.

Tech Stack

  • Query Understanding: GPT-4o-mini for intent parsing, related title extraction, and conversational re-synthesis
  • Embeddings: text-embedding-3-small (1536d) — pre-computed for 100K jobs, real-time for queries
  • Vector Search: FAISS IndexFlatIP (brute-force inner product) — 3 separate indices for explicit, inferred, and company embeddings
  • Data Processing: pandas + NumPy for ETL from 8.36 GB JSONL → Parquet + .npy arrays
  • Geo Filtering: Haversine distance with pre-computed coordinates for 1,000 US cities (Photon geocoder)
  • Web UI: Streamlit with custom-branded theme, job cards, and conversational interface
  • Language: Python 3.11+

Results & Performance

  • 95% Precision@5 across evaluated queries (18/19 relevant results in top 5)
  • ~$0.00017 per query — the $10 budget supports ~58,000 queries
  • ~50ms search latency on 100K vectors (exact brute-force search)
  • Cross-title recall: "someone who manages projects" surfaces Scrum Masters, Project Managers, and Program Managers
  • Geo-aware: "jobs in San Diego" returns only nearby cities (Chula Vista, Carlsbad), not all of California
  • Vague intent handling: "I want to help people with their finances" → financial advisor, financial planner, wealth manager

Design Trade-offs

  • FAISS brute-force over IVF/HNSW: 100K vectors is small enough for exact search (~50ms). Simpler, no training required, exact results.
  • GPT-4o-mini over GPT-4o: ~10× cheaper for query parsing. Adequate for intent extraction with structured JSON output.
  • Multi-query embedding over single-query: Embeds related titles separately so "data engineer" also matches "ETL developer". One batch API call → negligible extra cost.
  • Post-filtering over pre-filtering: Avoids partitioned indices. At 100K scale, over-fetch + filter is fast and never misses semantically relevant results.
  • Re-synthesis over incremental filters: Each refinement turn re-synthesizes full intent from conversation history. More robust for complex multi-turn queries.
  • 3 separate indices over concatenated: Allows dynamic per-query weight tuning. Company-focused queries boost company weight; skill queries boost explicit weight.

Challenges & Solutions

  • Scale & Data Wrangling: Processing 8.36 GB of messy, inconsistent JSONL data into clean Parquet + NumPy arrays with aligned row indices across metadata and three embedding matrices.
  • Cross-Title Recall: Single-vector search misses synonymous job titles. Solved by having GPT generate related titles and batch-embedding all variants in one API call for near-zero extra cost.
  • Location Ambiguity: String-matching "San" matches both "San Diego" and "San Francisco". Solved with haversine geo-distance filtering using pre-computed coordinates for 1,000 US cities.
  • Conversational Context: Simple filter accumulation breaks on complex multi-turn queries. Solved by re-synthesizing the full intent from conversation history each turn.
  • Cost Control: Kept total API spend under $0.01 for all development and testing by using GPT-4o-mini and batch embedding strategies.

Future Improvements

  • Hybrid re-ranking with BM25/TF-IDF text search fused via Reciprocal Rank Fusion
  • Negative filtering using embedding distance to exclude "not X" terms
  • Result explanations showing which embedding channel and related title contributed most
  • IVF or HNSW indices for production scale (millions of jobs)
  • Skills knowledge graph for expanded matching (e.g., "Python" → pandas, Django, FastAPI)
  • Saved searches, alerts, and per-user conversation history
